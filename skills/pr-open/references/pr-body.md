# PR の題と本文の書き方

`dev-relay pr create` が検査する形。検査の内容は `dev-relay pr check` で確かめられる。

## 題

- 何を変えたかを1行で書く。100文字以下。
- リポジトリのコミットや PR の題の決まり（接頭辞など）に合わせる。`dev-relay pr recent` の出力が材料になる。
- 手元のパスや秘密の値を入れない。題も検査される。

## 本文の形

見出しは英語のまま、次の順に並べる。中身は、決めた言語で書く。

| 節 | 書くこと |
|---|---|
| `## Why` | 何を解決するか。1〜3文。`dev` の最初に言い直した目的 |
| `## What changed` | 振る舞いの変化を箇条書きで。ファイルの一覧にしない |
| `## Scope` | 含めたものと、意図して含めなかったもの |
| `## Tradeoffs` | 選んだ方針と、捨てた代替案。設計書があれば、そこから |
| `## Blast Radius` | 壊れうる範囲、影響を受ける利用者や機能、戻し方 |
| `## Verification` | 実際に実行したコマンドと結果をフェンスで。続けて、使ったレビュアーと、指摘の採否の数を1〜2行で |

見出しは、行全体がこの文字列でなければならない（フェンスの中の見出しは数えない）。どの節も、空にしない。フェンスは必ず閉じる。中身の無いフェンスは、節の中身にも Verification のコマンドにも数えない。

リポジトリに PR のテンプレートがあるときは、テンプレートの見出しに従う。6つの節の内容は、テンプレートの見出しの下へ割り振る。その場合は `--no-sections` を付けて検査する。

## 決まり

- 1分で読める長さにする。フェンスの外で60行以下が目安。超えても作れるが、下書きを見せるときに長いと伝える。
- Verification には、このセッションで実際に実行したコマンドだけを書く。実行していなければ、今実行するか、「未実施」と書く。実行していない確認を、したように書かない。
- 出力は要点だけに縮める。手元のパス、秘密の値、顧客の名前を入れない。パスは、リポジトリのルートからの相対にする。
- レビュアーの行は、このセッションで採否を報告したレビューだけから書く。`.dev-relay/` には前の作業の結果も残っているので、ファイルを見つけただけで書かない。このセッションでレビューをしていなければ、行ごと省く。

## 例

作り物の内容。CSV を読む小さなコマンドに、区切り文字の指定を足した変更。

````markdown
## Why

`csvq` は、カンマ区切りの CSV しか読めない。タブ区切りのファイルを渡すと、1列として読まれ、集計が合わない。区切り文字を指定できるようにする。

## What changed

- `--delimiter` を追加した。1文字を受け取り、読み込みの区切りに使う。
- 指定が無いときは、これまでどおりカンマで読む。
- 1文字でない値は、使い方を添えて終了コード 2 で止まる。

## Scope

- 含めた: 読み込み時の区切り文字の指定。
- 含めなかった: 書き出し時の区切り文字。ファイルの拡張子からの自動判定。

## Tradeoffs

- 拡張子から区切りを推測する案は捨てた。`.txt` のように、拡張子では決まらないファイルがある。
- 区切りは1文字に限った。複数文字の区切りは、使う場面がまだ無い。

## Blast Radius

- 影響を受けるのは `csvq` の読み込みだけ。`--delimiter` を付けない呼び出しは、動きが変わらない。
- 戻すときは、この PR を revert する。保存データの形は変えていない。

## Verification

```
$ make test
ok   parse_delimiter (7 cases)
ok   read_tsv
ok   read_csv_default
PASS

$ printf 'a\tb\n1\t2\n' | ./csvq --delimiter '\t' sum b
2

$ ./csvq --delimiter ',,' sum b
error: --delimiter takes one character
exit=2
```

設計レビューとコードレビューを、別ベンダーのレビュアー1つで行った。指摘4件のうち、再現した2件を直し、2件は再現しなかったので直していない。
````
