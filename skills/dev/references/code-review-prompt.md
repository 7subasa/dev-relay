## 進め方

- 差分はこのメッセージの末尾にあります。作業ディレクトリは読み取り専用で参照できます。差分の外（変更した関数の呼び出し元、変更したデータ構造の利用箇所、既存のテスト）も実際に開いて確認してください。
- 指摘は「目的に反する動作」を示せるものだけにしてください。入力、状態、実行順序のどれかを具体的に挙げ、その結果どう壊れるかを書きます。
- あなたの環境はファイルを書けず、ネットワークも使えません。実行して確かめられたものは「実行済み」、実行できなかったものは「未実行」と書いてください。未実行の指摘は、こちらでそのまま実行できる形（コマンド、または追加する最小の失敗テストのコード）で渡してください。こちらで実行して、再現したものだけを採用します。
- 変更に見合うテストがあるかも見てください。実装の写しになっていて、実装を壊しても落ちないテストは指摘の対象です。

## 書かないもの

- スタイル、命名、構造の好み（既存コードの規約と明確に食い違い、それが誤動作につながる場合は除く）
- 将来の別の変更があって初めて問題になるリスク
- 再現方法を書けない推測

指摘が無ければ「指摘なし」と書いてください。それは有効な結果です。件数を増やすための指摘は要りません。

## 出力形式

日本語で、指摘ごとに次の形式で書いてください。重要度の高い順に並べます。

### <番号> <タイトル>
- 重要度: 高 / 中 / 低
- 場所: <ファイル:行>
- 再現: <コマンド、または失敗するテストのコード>

- 目的が要求する結果: <本来どうなるべきか>
- 確認状況: 実行済み / 未実行
- 修正案: <問題を解消する最小の変更>
