# Cursor CLI リファレンス（このスキルが使う範囲）

2026年11月時点（cursor-agent 2026.11.10 で確認）の仕様。Cursor CLI は更新が速いので、フラグが通らないときは `cursor-agent --help` で確かめる。

## インストールと認証

インストールは、公式の案内（https://cursor.com/docs/cli/overview）に従う。このスキルからは行わない。

```bash
cursor-agent --version
cursor-agent login            # ブラウザで認証
cursor-agent status
```

CI など対話ログインができない環境では、`CURSOR_API_KEY` 環境変数で認証できる。

`cursor-agent status` は、未ログインでも終了コード 0 で終わり、`Not logged in` と出力する。終了コードでは判定できないので、`dev-relay` は出力の文言（`Logged in` の有無）で判定する。CLI の文言が変わると、ログイン済みでも `cursor-not-logged-in` で飛ばされることがある（候補が使われないだけで、誤って送ることは無い）。`CURSOR_API_KEY` だけで認証しているときの出力は確かめていない。

## このスキルの呼び方

スクリプトは次の形で Cursor CLI を1回だけ実行する。

```bash
cursor-agent -p --mode ask --trust [--model <モデル名>] --output-format json --workspace <リポジトリのルート> < <依頼文のファイル>
```

- `-p` は非対話実行。依頼文は標準入力から渡す。
- `--mode ask` は、読み取り専用のモードで動かす指定。
- モデル名は、役割のファイル（`config/roles/`）の候補の `model` 列から渡す。Cursor ではモデル名に推論量が含まれる（例: `gemini-4-carbon-medium`、`grok-4.7-high`）ので、`effort` 列は使わない。
- **`dev-relay review` の `--model` と `--effort` は、Cursor のレビュアーには使えない**（終了コード 1）。Cursor ではモデルを変えると、送り先と課金の扱いが変わる。置き換えを許すと、送り先の許可と `metered` の判定をすり抜けてしまう。別のモデルを使いたいときは、`config/roles/` の役割のファイルに候補を足して、`--reviewer` で選ぶ。
- `jq` が要る。標準出力の JSON を `jq` で読む。

## JSON 出力

標準出力に、1行の JSON が出る。スクリプトが使う項目は次のとおり。

| 項目 | 内容 |
|---|---|
| `result` | レビューの本文 |
| `is_error` | 失敗かどうか |
| `duration_ms` | 実行時間（ミリ秒） |
| `usage.inputTokens` / `outputTokens` / `cacheReadTokens` / `cacheWriteTokens` | トークン数 |

`result` を結果ファイルの本文にし、`duration_ms` と `usage` を結果ファイルの末尾の2行（`duration_ms` と `tokens`）に書く。

次のどれかのとき、失敗として終了コード 10 にする。標準エラーには、CLI の標準エラー出力の末尾が出る。

- CLI の終了コードが 0 以外（存在しないモデル名は終了コード 1 になる）
- 出力が JSON でない
- `is_error` が `false` でない
- `result` が空

## `--mode ask` でできること

`--mode ask` でも、読むだけのコマンドは実行される。書き込みのコマンドを実行させようとしてもモデルが実行しなかったが（`--sandbox enabled` を付けても同じ）、OS の仕組みで書き込みが禁止されているかは確かめられていない。Codex の読み取り専用サンドボックス（`codex-cli.md`）とは強さが違う。

## 作業ツリーの検査

書き込みを防ぐ仕組みを確かめられていないので、`dev-relay review` は、Cursor を実行する前後で作業ツリーの一覧を取り、違っていたら終了コード 5 にする。

- 一覧は、`git status`、`git ls-files --stage`、追跡ファイル全体の実行権限とシンボリックリンクかどうか、変更または未追跡のファイルの中身のハッシュ（改行の変換をかけない）、シンボリックリンクの向き先を並べたもの。ステージ済みのファイルの書き換え、すでに変更のあるファイルへの追記、改行の変換、実行権限の変更、シンボリックリンクの向き先の変更、未追跡ファイルの追加は、検出できる。
- 違っていたら、前後の差のうち変わったパスの行を、結果ファイルの `## 作業ツリーの変化を検出` の節に書く。
- スクリプトは元に戻す操作をしない。実装者の作業を消すおそれがあるため。変えたのが誰か（レビュアーか、同時に動いていたテストなどか）は、メインセッションが判断する。
- 終了コード 5 は、CLI の失敗（10）やタイムアウト（124）より優先する。どちらが起きたかは、結果ファイルに両方書かれる。

検査の限界:

- 無視されているファイル（`.gitignore` の対象）と、`.git/` の中は見ない。
- git が変更とみなさない内容の変化（改行の変換フィルターが吸収するものなど）は、すでに変更のあるファイルでしか検出しない。
- submodule の中の変更は、親リポジトリから見た状態が変わるときだけ検出する。
- 同時に別の作業（テストの実行など）が、無視されないファイルを作ると、誤って検出される。Cursor のレビューが動いている間、メインセッションは作業ツリーに書き込まない。
- 結果ファイルは、git に無視される場所か、作業ツリーの外に置く（別のレビューの結果ファイルが検査に混ざらないようにするため。置き場所が条件に合わなければ、終了コード 1 になる）。

## 自動で読まれるファイル

Cursor CLI は、プロジェクト直下の `CLAUDE.md`、`AGENTS.md`、`.cursor/rules` を自動で読む。止める設定は無い。リポジトリのこれらのファイルに書いた内容が、レビュアーの判断に影響する。

## 課金

役割のファイルで `billing` が `metered` の候補（既定では追加のレビュアーの1つ）は、利用量に応じて課金されうる。設定の `metered` が `auto` のときだけ選ばれる（`reviewers.md`）。結果ファイル末尾のトークン数は、使った量の目安になる。
