# 指摘の採否と報告

レビュアーを使う目的は、独立した視点を得て、採否をメインセッションとユーザーで決めることにある。レビュアーの言う通りにすることではない。レビュアーも間違える。出力をそのまま貼って終わりにすると、ユーザーは何を信じてよいか判断できない。指摘1件ごとにメインセッションの判断を付ける。

## 採否の決め方

採否は、指摘が実際に再現するかどうかで決める。読んだ印象で決めると、もっともらしい誤った指摘で直したり、正しい指摘を言い負かしたりする。

| 区分 | 基準 |
|---|---|
| 採用 | 再現した。または、根拠のコード箇所を開いて確かめたら指摘どおりだった |
| 不採用 | 再現しなかった、事実誤認だった、目的の範囲外だった、意図して選んだトレードオフだった。理由を必ず書く |
| ユーザー判断 | 正しいが、範囲や方針の選択に関わる。または下の「再現できなくてもユーザーに聞くもの」に当たる |

### コードレビューの指摘

1. 明らかな事実誤認（存在しない関数を挙げている、差分を読み違えている）は、コードを開いて確かめたうえで不採用にする。
2. 残りは採用候補として実装者に差し戻す。実装者は、指摘に付いている再現方法を実行する。文面は `implementer-prompt.md` の「差し戻しの文面」を使う。
3. 再現したものは、失敗するテストを残して修正する。これを採用とする。
4. 再現しなかったものは修正しない。不採用とし、「再現せず」と、実行したコマンドを記録する。
5. 1行で済む修正は、差し戻さずにメインセッションが直してよい。その場合も再現は自分で確かめる。

### 設計レビューの指摘

1. 根拠として挙げられたファイル:行を開いて、指摘どおりかを確かめる。
2. 「実行すれば決まること」に挙がった確認方法は、メインセッションが実行して結果で決める。動かせば分かることをユーザーに尋ねない。ユーザーに聞くのは、実行しても決まらない好みや方針の選択だけにする。
3. 採用した指摘を設計書に反映する。

### 再現できなくてもユーザーに聞くもの

次に関わる指摘は、再現できなかった場合でも不採用にせず、ユーザー判断に回す。見逃したときの損害が大きく、再現条件を作るのが難しいことが多いため。

- 認証・認可、機密情報の漏れ
- データの消失や破損、移行
- 課金や金額の計算
- 並行実行時の競合

迷ったら聞く。雑音を1件ユーザーに見せる手間は小さく、本物を1件見逃す損害は大きい。

## 往復の上限

設計レビューもコードレビューも、再レビューは1回まで（合計2往復）。往復を重ねると指摘は細部の好みに寄っていき、レビューにかかる時間に見合わなくなる。それでも残る論点は、設計や実装の誤りではなく方針の選択なので、ユーザー判断に回す。

再レビューするのは、設計が大きく変わったとき、または修正量が多いときだけにする。

## 報告の形式

```
## レビュー結果（<設計|コード> / レビュアー: <id（backend / model）。複数なら並べる。代替したときはその旨>）

**目的**: <最初に言い直した目的>

**要約**: <1〜2文。重大な指摘があったか、全体の評価>

| # | 指摘 | 重要度 | 再現 | 判断 | 対応・理由 |
|---|------|--------|------|------|-----------|
| 1 | ... | 高 | した | 採用 | 失敗するテストを追加し、...を修正した |
| 2 | ... | 中 | せず | 不採用 | <実行したコマンド> で再現しなかった |
| 3 | ... | 中 | 未確認 | ユーザー判断 | A案とB案のどちらにするか決めてほしい |

**追加のレビュアー**: <使ったときだけ。追加した理由と、結果ファイル末尾のトークン数を1行で>

**確認したこと**: <メインセッションが自分で実行したコマンドと、その出力の要点>

**次のアクション**: <実装に進む / 修正して再レビュー / ユーザーの回答待ち / コミット待ち>

詳細: `<結果ファイルのパス>`
```

- 重要度はレビュアーが付けたものを使う。無ければメインセッションが決める。
- 表が10行を超えそうなときは、重要度「低」をまとめて1行にし、結果ファイルへ誘導する。
- 設計レビューでは「再現」列に、根拠を確かめたか（確認済み / 相違あり）を書く。
- 「確認したこと」には、実装者の報告ではなく、メインセッション自身が実行した結果を書く。
- 追加のレビュアーを使ったときは、使った理由（`reviewers.md` の基準のどれに当たったか）と、結果ファイル末尾のトークン数を、「確認したこと」の前に1行で書く。
- 複数のレビュアーが同じ指摘をしたときは、表の1行にまとめ、誰が挙げたかを書く。
