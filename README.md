# dev-relay

設計・実装・レビューを、別々のモデルに分担させる Claude Code プラグイン。

同じモデルが書いたものを同じモデルが確かめると、同じ前提と同じ見落としが残る。そこで、設計はメインセッション、実装は Claude Code のサブエージェント、レビューは別ベンダーのモデルが受け持つ。レビューの指摘は、再現できたものだけ採用する。

## 必要なもの

- Claude Code
- 任意: Codex CLI、Cursor CLI と `jq`、Herdr、GitHub CLI（`gh`。`/dev-relay:pr-open` で PR を作るときと、`/dev-relay:pr-respond` でレビューに対応するときに要る）
- 対応 OS: macOS と Linux

どれも無くても、Claude の別モデルがレビュアーになり、同じ手順が最後まで進む。

## インストール

```
/plugin marketplace add mk-edu/dev-relay
/plugin install dev-relay@dev-relay
/dev-relay:setup
```

`/dev-relay:setup` は、道具の状態を調べ、コードを送ってよい提供元と、追加のレビュアーを使うかを選択式で決める。

## 使い方

`/dev-relay:dev` を使う。モードは3つ。

- `full`: 機能追加や複数ファイルの変更。設計書 → 設計レビュー → 実装 → コードレビュー。
  例: 「検索結果にページ送りを足したい。full で進めて」
- `bugfix`: 不具合の修正。再現 → 原因メモ → 失敗するテスト → 修正 → コードレビュー。
  例: 「中央値の計算が偶数個のときに間違う。bugfix で直して」
- `review`: すでにある差分のコードレビューだけ。
  例: 「この差分を review でレビューして」

PR は `/dev-relay:pr-open` で作る。今のブランチの変更を、Why / What changed / Scope / Tradeoffs / Blast Radius / Verification の6つの節でできた本文にまとめる。宛先（アカウント、リポジトリ、ブランチ）と本文を見せ、承認されてから push と PR の作成を行う。リポジトリごとに、初めて使うときに1度だけ、PR 機能を使ってよいかを尋ねる。`github.com` のリポジトリだけが対象で、フォークから元のリポジトリへの PR は作らない。
例: 「この変更で PR を作って」

自分の PR にレビューが付いたら、`/dev-relay:pr-respond` で対応する。未解決のスレッド、レビューの本文、会話のコメント、CI の失敗を一覧にし、コメントごとに「直す / 理由を付けて直さない / 利用者に聞く」を分ける。修正の差分、返信の下書き、宛先をまとめて見せ、承認1回で、コミット、push、返信の投稿、CI の再実行を行う。マージ、force-push、スレッドの解決、他人のコメントの編集はしない。対応済みかどうかは GitHub 上の印で決めるので、同じ PR に対して、別の場所から同時には動かさない。
例: 「レビューのコメントに対応して」

### 作業のファイル

設計書、レビューの結果、実装者への指示と報告、PR の下書きは、リポジトリの `.dev-relay/` に置かれる。中身はすべて git に無視される。

```
.dev-relay/
├─ <topic>/          1件の作業（design.md と review/、impl/、logs/）
├─ pr/<branch>/      PR の本文の下書き、届いたレビューの一覧、返信の下書き、CI のログ
└─ done/             終わった作業
```

作業がコミットされると、`dev-relay work done <topic>` でそのフォルダが `done/` に移る（消さない）。要らなくなったら `.dev-relay/done/` を自分で消してよい。以前の版で直下に作られたファイルは、自動では移さない。

## 道具が無いときの動き

候補のレビュアーのうち、使えるものを上から選ぶ。コードの送り先がすべて許可されている場合の例:

| 環境 | 設計・コードレビュー | 追加のレビュアー |
|---|---|---|
| Codex あり、Cursor あり | Codex | 設定が `auto` なら Cursor 経由のモデル、`off` なら Claude |
| Codex あり、Cursor なし | Codex | Claude |
| Codex なし、Cursor あり | Cursor 経由のモデル | 設定が `auto` なら Cursor 経由の別のモデル、`off` なら Claude |
| どちらもなし | Claude | なし |

許可が無ければ、どの環境でも Claude になる。Claude で代替したときは、独立性が落ちる。報告にその旨が書かれる。

## レビュアーの選ばれ方と設定の変え方

- 今どのレビュアーが選ばれるか、何が飛ばされたかは `dev-relay doctor` で分かる。
- 追加のレビュアーを使うかは `dev-relay config metered` で見て、変える。
- コードを送ってよい提供元は `dev-relay config vendors` で見て、変える。リポジトリごとの設定が、利用者の既定より優先する。
- 役割ごとの候補は、`dev-relay config role` で手元の設定として上書きできる。
- 設定はプラグインの外に保存される。プラグインを更新しても消えない。

## 最新に保つ

CLI の更新やモデルの入れ替わりで、レビュアーの割り当てが古くなったり動かなくなったりすることがある。`/dev-relay:refresh` で、変化を確かめて見直せる。

- `/dev-relay:refresh`: 前回の確認からの変化（CLI の版、モデルの一覧、既定のモデル）を一覧にし、公開ページを読んで割り当ての変更案を出す。承認した変更だけを、手元の設定に書く。プラグインのフォルダには書かない。
- 通知: セッションの開始時に、CLI の版が変わったとき、見直す予定の日を過ぎたとき、上書きの元の既定値が変わったとき、前回の確認から30日たったときに、1行で知らせる。`/dev-relay:refresh` を実行すると止まる。通知そのものを止めるときは `dev-relay config notice off`。
- スモークテスト: `dev-relay smoke` は、本物のレビュアーを小さい作り物の差分に対して動かし、指定の出力形式で指摘が返るかを確かめる。許可された提供元に、作り物の差分が送られる。`metered` が `auto` のときは、課金されうる候補も動く。
- プラグインの更新: Claude Code の `/plugin` でマーケットプレイスを更新し、dev-relay を更新する。設定と記録はプラグインの外にあるので、更新しても消えない。更新でプラグインの既定のレビュアー候補が変わると、手元で上書きしている役割は通知で分かる。

## 注意

- **送り先**: 選ばれたレビュアーの提供元（OpenAI、Cursor とその先のモデル提供元）に、差分と設計書が送られる。`--dry-run` を付けると、送る内容だけを出力して終わる。入れただけでは外部に送らない。`setup` で選んだ送り先にだけ送る。
- **インストール**: `setup` は、利用者が選んだときだけ Herdr（`hc`）のインストーラを実行する。それ以外の道具は入れない。
- **費用**: 追加のレビュアーは、利用者自身の契約によっては、利用量に応じた料金がかかることがある。既定では無効で、`setup` で有効にしたときだけ使われる。
- **自動で行う操作**: レビューとテストの実行。セッションの開始時に、CLI の版を調べる（ネットワークは使わない）。設定フォルダに、前回の確認の記録を書く。コミットは、ユーザーの指示があってから行う。push と PR の作成は、`pr-open` が下書きを見せて承認されたあとに行う。レビューへの対応のコミット、push、返信は、`pr-respond` が見せて承認されたあとに行う。マージと force-push は行わない。PR は、`gh` で有効なアカウントの名義で作られる。
