# dev-relay

設計・実装・レビューを、別々のモデルに分担させる Claude Code プラグイン。

同じモデルが書いたものを同じモデルが確かめると、同じ前提と同じ見落としが残る。そこで、設計はメインセッション、実装は Claude Code のサブエージェント、レビューは別ベンダーのモデルが受け持つ。レビューの指摘は、再現できたものだけ採用する。

## 必要なもの

- Claude Code
- 任意: Codex CLI、Cursor CLI と `jq`、Herdr
- 対応 OS: macOS と Linux

どれも無くても、Claude の別モデルがレビュアーになり、同じ手順が最後まで進む。

## インストール

```
/plugin marketplace add mk-edu/dev-relay
/plugin install dev-relay@dev-relay
/dev-relay:setup
```

`/dev-relay:setup` は、道具の状態を調べ、コードを送ってよい提供元と、追加のレビュアーを使うかを選択式で決める。

## 使い方

`/dev-relay:dev` を使う。モードは3つ。

- `full`: 機能追加や複数ファイルの変更。設計書 → 設計レビュー → 実装 → コードレビュー。
  例: 「検索結果にページ送りを足したい。full で進めて」
- `bugfix`: 不具合の修正。再現 → 原因メモ → 失敗するテスト → 修正 → コードレビュー。
  例: 「中央値の計算が偶数個のときに間違う。bugfix で直して」
- `review`: すでにある差分のコードレビューだけ。
  例: 「この差分を review でレビューして」

## 道具が無いときの動き

候補のレビュアーのうち、使えるものを上から選ぶ。コードの送り先がすべて許可されている場合の例:

| 環境 | 設計・コードレビュー | 追加のレビュアー |
|---|---|---|
| Codex あり、Cursor あり | Codex | 設定が `auto` なら Cursor 経由のモデル、`off` なら Claude |
| Codex あり、Cursor なし | Codex | Claude |
| Codex なし、Cursor あり | Cursor 経由のモデル | 設定が `auto` なら Cursor 経由の別のモデル、`off` なら Claude |
| どちらもなし | Claude | なし |

許可が無ければ、どの環境でも Claude になる。Claude で代替したときは、独立性が落ちる。報告にその旨が書かれる。

## レビュアーの選ばれ方と設定の変え方

- 今どのレビュアーが選ばれるか、何が飛ばされたかは `dev-relay doctor` で分かる。
- 追加のレビュアーを使うかは `dev-relay config metered` で見て、変える。
- コードを送ってよい提供元は `dev-relay config vendors` で見て、変える。リポジトリごとの設定が、利用者の既定より優先する。
- 設定はプラグインの外に保存される。プラグインを更新しても消えない。

## 注意

- **送り先**: 選ばれたレビュアーの提供元（OpenAI、Cursor とその先のモデル提供元）に、差分と設計書が送られる。`--dry-run` を付けると、送る内容だけを出力して終わる。入れただけでは外部に送らない。`setup` で選んだ送り先にだけ送る。
- **インストール**: `setup` は、利用者が選んだときだけ Herdr（`hc`）のインストーラを実行する。それ以外の道具は入れない。
- **費用**: 追加のレビュアーは、利用者自身の契約によっては、利用量に応じた料金がかかることがある。既定では無効で、`setup` で有効にしたときだけ使われる。
- **自動で行う操作**: レビューとテストの実行。コミットは、ユーザーの指示があってから行う。push、PR の作成、マージは行わない。
